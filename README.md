## 一、项目简介

云南山地农户居住分散、农技资源匮乏，特色经济作物病害资料稀缺，误诊误治造成严重损失。**云岭农诊**通过「拍照识别 → 多 Agent 分级诊疗 → 知识库问答」的完整闭环，让农户用一部手机就能获得专业级病虫害诊断与安全用药指导。

**一分钟了解它**：农户拍一张病叶照片 → 初诊 Agent 用视觉大模型识别病斑 → 结果过安全闸门（置信度/检疫性/禁用药三道硬校验）→ 用药指导 Agent 基于专属知识库生成防治方案 → 农户拿到分级清晰的诊断报告，低置信病例自动流转农技站人工复核。

## 三、AI 技术架构

```
┌─ 前端 Vue3/TS ─────────────────────────────────────────┐
│  拍照上传 / 图文速查 / 流式问答 / Agent轨迹可视化 / 后台   │
└──────────────────────┬─────────────────────────────────┘
                       │ HTTP (X-Token HMAC 会话)
┌──────────────────────▼─────────────────────────────────┐
│ Node.js/Express AI 接入层                               │
│                                                        │
│  ① 初诊 Agent ── Qwen3-VL-8B 视觉模型                   │
│      └─ 分层提示词（角色/候选病害约束/输出JSON契约）        │
│  ② 安全闸门 ── 规则引擎（不经 LLM，确定性执行）            │
│      ├─ 置信度阈值 → 低于阈值强制转人工                   │
│      ├─ 禁药黑名单（甲胺磷等 8 类国家禁用药）硬拦截         │
│      └─ 检疫性病害 → 最高级警示标记                       │
│  ③ 用药指导 Agent ── DeepSeek-V3.2 + RAG 上下文注入      │
│  ④ QA 问答 Agent ── Function Calling 自主工具循环         │
│      ├─ get_weather_forecast → Open-Meteo 真实气象API    │
│      └─ lookup_pesticide_safety → 农药安全库             │
│                                                        │
│  RAG：BM25 打分 + 同义词扩展 + 多字段加权（名称×3/别名×2.5 │
│       /症状×2/关键词×1.5），scoreNormalized 归一化输出     │
│  降级链：AI超时/断网 → 规则引擎诊断 → 知识库直出方案        │
│         → 模拟气象源，任何一层失败服务不崩                │
└────────────────────────────────────────────────────────┘
```

**为什么初诊→用药用固定编排而不是模型自主决策？** 我们把诊断链路固定编排，而不是交给模型自主决策，主要是出于农业用药安全考虑：农药使用风险高，整个诊断流程必须可以追溯、核验。所以我们把自由决策放在风险更低的问答工具调用环节。

**AI 接入层 API 一览**

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/api/diagnose` | 多 Agent 诊断（图/文/图文） |
| GET  | `/api/records` | 诊断记录（支持 cropId/days 过滤） |
| POST | `/api/qa` | 流式知识库问答 |
| POST | `/api/advisory` | Function Calling 咨询（模型自主调工具） |
| GET  | `/api/weather` | 农区天气 + 病害风险 + 灾害预警 |
| GET  | `/api/kb/diseases` | 病害图谱数据 |
| GET  | `/api/metrics` | 模型调用指标（token/耗时/失败） |
| GET  | `/api/health` | 服务健康检查 |
| GET  | `/api/retrieve?q=` | 检索调试（RAG 可观测性） |

## 四、竞品对比
市面上常见拍照识虫小程序大多只输出病害名称，缺少用药安全校验；直接调用通用大模型问答，容易产生幻觉，给出违规农药方案。

云岭农诊针对性解决了这个痛点：诊断链路输出完整、可追溯的诊疗流程，依托自研BM25 RAG知识库接入云南本地作物资料，内置禁药拦截规则；当诊断置信度偏低时，会自动流转给农技人员人工复核，而不是直接把不确定结果给到农户。

一句话差异：竞品输出「识别结果」，我们输出「可追责的诊疗决策链路」——每一步Agent做了什么、为什么拦截、依据哪条知识库，全部可视化。

## 五、社会价值与成本考虑
- 面向云南山地农户设计，界面简化、支持语音播报，降低山区农户上手门槛，适配低学习成本的使用场景。
- 诊断结果附带知识库来源，农户和农技专家都可以核对依据，减少盲目用药，规避农药误用风险。
- 低置信病例自动转入人工复核工单，农技人员在后台审核、维护作物知识库，知识库可以持续沉淀迭代。
- 项目做了AI降级兜底设计：大模型服务不可用时，问答、诊断依然可以走本地规则引擎+知识库直出方案，保证演示稳定可用。
- 单次诊断Token消耗可控，调用成本低，免费额度就可以支撑上千次诊断，适合基层长期试用。

## 六、降级设计（演示保障）

| 故障场景 | 系统行为 |
|----------|----------|
| AI 未配置 | 初诊走规则匹配，用药方案由知识库直出，前端标注「降级运行」 |
| 视觉模型超时 | 自动重试 2 次（指数退避），仍失败转规则路径 |
| 模型输出非法 JSON | 三级容错解析（围栏剥离 → 大括号截取 → 数组截取） |
| 模型推荐禁用药 | 农药黑名单硬校验，自动移除并告警 |
| 置信度 < 40% | 强制标注「建议咨询农技人员」 |
| 真实气象 API 不可用 | 6 秒超时自动降级确定性模拟气象源 |
| 照片中无病斑 | 友好提示重拍或补充症状描述，不报 500 |

# 配置 AI（.env，可申请硅基流动免费额度）
